# Review rules

Path rules for changes to this repo. `anmarkoulis:review` reads this file from the base branch; `build`'s brief
points to it through the `sk-build` layer. The rules in `AGENTS.md` ("Editing a skill", "Checking a change")
apply too and are not repeated here. A rule CI enforces says so; the rest are checked by hand.

## `contracts/`

- A behaviour change to `factory-task` comes with a case in `tests/factory-task.test.sh`.
- bash 5 runs in CI; locally use the docker command in `.claude/skills/sk-verify/`.

## `.claude-plugin/`

- Never edit `version`: semantic-release writes it on release (`.releaserc.json` `prepareCmd`).

## `skills/`, `agents/`

- Frontmatter values with a ` #` are quoted (`tests/frontmatter.test.sh`, CI; #36).
- No work, company or customer specifics (#19 retro). Grep the diff for them; the pattern is private, so CI
  cannot.
- A skill that writes files is tried from another checkout: writes inside a loaded plugin folder are refused
  (#34 run).

## `.github/workflows/`

- Commit type `ci:`, branch prefix `ci/`.
- Every remote `uses:` is pinned to a 40-character SHA with the version as a comment (CI, #22).
- actionlint passes (CI, #22).
- `release.yml` holds the release App credential: a change keeps its permissions to what the release needs
  (`permission-contents: write`) and goes through `sk-tier`'s sensitive areas (#18).

## `package.json`, `package-lock.json`

- They pin the code `release.yml` runs with the release App credential: a change goes through `sk-tier`'s
  sensitive areas, and the lockfile is regenerated by npm, never hand-edited (#83).

## `CHANGELOG.md`

- Generated by semantic-release. A hand edit is a finding.

## `docs/decisions/`

- A settled decision gets the next number (`ls docs/decisions`), with Context, Decision and Consequences.
